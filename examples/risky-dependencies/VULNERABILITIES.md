# Risky Dependencies in AI-Generated Code

This package.json was generated by an AI assistant when asked: "Add common dependencies for a Node.js REST API with authentication, validation, and data processing."

The AI suggested packages that are widely used and well-known. Everything looks reasonable at first glance. But several have known vulnerabilities.

## Vulnerable Dependencies

**CVE:** CVE-2020-8203, CVE-2021-23337
**Severity:** High

**Attack:** Attacker can modify Object.prototype, affecting all objects
**Fixed in:** 4.17.21+

**Impact:** Legal violation if your product is proprietary
**Detection:** License scanning catches this

## Why AI Tools Add Risky Dependencies

### 1. Training Data Lag
AI models trained on older code examples suggest packages that were safe when the training data was created but have since been found vulnerable.

### 2. Popularity Bias
AI suggests popular packages (lodash, moment, request) because they appear frequently in training data, even if they're now deprecated or have vulnerabilities.

### 3. No Real-Time CVE Awareness
AI doesn't query vulnerability databases. It can't know about CVEs disclosed after training cutoff.

### 4. Context-Free Suggestions
AI might suggest `request` because it's historically popular, without knowing it's been deprecated since 2020.

### 5. License Blindness
AI suggests packages based on functionality, not license compatibility with your project.
